# Дополнительные источники данных — что мы проверили

Мы посмотрели **Bloomberg** для премиальных новостей и **Polymarket**, **Kalshi**
и **ForecastEx** для вероятностей событий. Polymarket технически доступен, но
для нашей интеграции нужно письменное разрешение на использование данных;
ForecastEx стоит попробовать.

## Bloomberg — нет

У Bloomberg лучшие данные. **Проблема в их договоре, а не в цене.**

Их лицензия, которую мы прочитали сами, запрещает хранить данные в базе,
передавать их кому-либо, использовать в автоматизированной системе и
подключаться с машины, не залогиненной в Терминал. Наш сервис делает всё
четыре. Место стоит **$31 980 в год**, и покупка не помогает — ограничения идут
вместе с ним.

Есть фиды, для которых Терминал не нужен, но они рассчитаны на торговые
подразделения, а не на показ читателям. Единственный продукт, где публикация
*разрешена*, — отдельный медиа-бизнес, и продаётся он по темам («Технологии»,
«Энергетика»), а не по компаниям. То есть даже за деньги он не отвечает на
вопрос «новости по этой компании».

Это не изменится: их лицензия закрывает всё, что может заменить подписку на
Терминал.

## Polymarket — доступ возможен; разрешение на внутреннее использование нужно подтвердить

**Публичные данные получить можно, но письменное разрешение на их использование
в нашей внутренней системе пока не подтверждено.** Текущий сценарий — аналитика
для сотрудников, без торговли, публичного показа и передачи данных клиентам.
Само по себе внутреннее использование не снимает ограничения условий.
При проверке 8 сентября 2026 года прямые
запросы к проверенным адресам Polymarket завершались сбросом соединения. Однако
через внешний сервис чтения страниц удалось получить запись о рынке из
публичного Gamma API и время сервера CLOB — без VPN и аккаунта. Это подтверждает
возможность получения данных по другому сетевому маршруту, но ещё не надёжность
подключения для рабочего продукта. Для чтения публичных рыночных данных
регистрация не нужна; для регистрации и торговли действуют отдельные требования
к местоположению.
[Документация API](https://docs.polymarket.com/market-data/discover-markets).

**Как подключаться после согласования прав:**

| Интерфейс | Что получаем |
| --- | --- |
| [Gamma API](https://docs.polymarket.com/market-data/discover-markets) | События и рынки, описания, варианты исхода, сроки, статус и объёмы торгов |
| [CLOB API](https://docs.polymarket.com/market-data/prices-order-books) | Цены контрактов, заявки на покупку и продажу, историю цен |
| [WebSocket](https://docs.polymarket.com/market-data/realtime-data) | Поток обновлений по постоянному соединению |

Для внутреннего дашборда достаточно периодических запросов: серверная задача
выбирает нужные события, получает данные раз в несколько минут с соблюдением
лимитов API, сохраняет историю в согласованном объёме и показывает её сотрудникам.
Например, можно отслеживать рыночную оценку вероятности снижения ставки ФРС
рядом с соответствующими новостями. WebSocket нужен,
если потребуются обновления почти в реальном времени. **Скрейпинг не требуется
и отдельно запрещён пунктом 4.2 условий.**
[Официальные условия](https://docs.google.com/document/d/1N4aYlRcqaWCeKMID7vUSWJ1UPMvw_v6SP4cOFN8ZxR4/preview).

**Полный текст условий тоже удалось получить автоматически.** Страница условий
содержит встроенный Google Doc, который мы скачали целиком. Проверенная редакция
действует с 11 августа 2026 года. Пункт 4.2 отдельно ограничивает **доступ к данным
и их использование** указанными профессиональными участниками рынков капитала,
в перечне которых названы финтех-компании, и распространителями рыночных данных;
для них требуется письменное соглашение. Он также отдельно ограничивает
**передачу данных** этим категориям получателей. Поэтому отсутствие внешней
публикации не снимает первое ограничение. Явного исключения для внутренней
аналитики или тестового проекта в проверенной редакции не найдено.

Применимость определения зависит от деятельности конкретного юридического
лица: не любая компания с названием «финтех» автоматически относится к этой
категории. Для нашего инвестиционного продукта рассчитывать на исключение без
уточнения оснований нет. Ограничения охватывают данные из API и блокчейна —
исходные, производные, агрегированные и обезличенные. Сам по себе ответ публичного
API без ключа не даёт необходимых прав и не подтверждает разрешение на регулярный
сбор данных для нашей системы.
[Официальные условия](https://docs.google.com/document/d/1N4aYlRcqaWCeKMID7vUSWJ1UPMvw_v6SP4cOFN8ZxR4/preview).

**Какие права нужно подтвердить для проекта:**

| Планируемое использование | Права, которые нужно согласовать |
| --- | --- |
| Показывать вероятности событий сотрудникам во внутреннем дашборде | Внутренний доступ и использование |
| Сохранять цены и строить исторические графики | Хранение и использование исторических данных |
| Рассчитывать показатель настроений на основе рыночных цен | Использование производных данных |

Публичный показ или передача через наш API клиентам потребуют отдельного
согласования, если впоследствии расширим сценарий использования.

ICE объявила об эксклюзивной дистрибуции данных Polymarket для **институциональных
рынков капитала**. Polymarket предлагает соответствующим компаниям обратиться
в свою команду лицензирования и в ICE. **Соглашение прежде всего даёт право
использовать данные для согласованной задачи; это не обязательно покупка ключа
API**, поскольку многие публичные запросы уже доступны без авторизации.
Канал поставки согласуется отдельно: разрешат существующий публичный API либо
предложат институциональную поставку, в том числе через ICE. Проверенные
источники не доказывают, что любая одобренная коммерческая интеграция обязана
использовать фид ICE. Цена и возможность бесплатного тестового доступа неизвестны.

Практический следующий шаг — запросить узкое разрешение на **внутреннюю аналитику
сотрудников, без торговли и передачи данных за пределы компании**, указав нужные
поля, срок хранения истории и число сотрудников с доступом. Нужно подтвердить
права из таблицы, стоимость и разрешённый способ подключения. В рамках этой
проверки запрос на лицензирование ещё не отправлялся.
Контакт — **data-licensing@polymarket.com**.
[Объявление ICE](https://ir.theice.com/press/news-details/2026/ICE-Launches-Polymarket-Signals-and-Sentiment-Tool-Turning-Crowd-Sourced-Dynamic-Views-into-Market-Opportunities/default.aspx),
[Информация о лицензировании Polymarket](https://institutional.polymarket.com/).

**Если пока не писать им**, можно подготовить интеграцию по документации на
синтетических данных. Для запуска регулярного сбора настоящих данных нужно
сначала подтвердить права. В проверенных условиях нет явного исключения для
внутреннего тестирования.

**VPN не решает вопрос прав на данные или допуска к торговле.** Пункт 4.1
запрещает использовать VPN и аналогичные инструменты для обхода ограничений.
Пункт 1 отдельно допускает информационный просмотр пользователями из юрисдикций
с ограничениями; это не разрешение на торговлю или нашу коммерческую интеграцию.
[Официальные условия](https://docs.google.com/document/d/1N4aYlRcqaWCeKMID7vUSWJ1UPMvw_v6SP4cOFN8ZxR4/preview).

## Kalshi — нет

Полноценно регулируемая американская биржа, выглядела перспективно. Но их
developer agreement, который мы прочитали сами, ограничивает API
*«обслуживанием собственной торговли участника»* и запрещает *«сбор,
кэширование, агрегацию и хранение данных»*.

Проще говоря: **их API — чтобы торговать, а не чтобы строить на нём продукт.**
Показ их цен пользователям — ровно то, что запрещено. Плюс тоже заблокирован на
сети.

## ForecastEx — стоит попробовать

**Этот вариант работает.** ForecastEx — американская биржа под регулированием
CFTC, и это регулирование **обязывает её публиковать дневные цены.** Она их и
публикует — обычными CSV-файлами на сайте.

Мы их скачали: без ключа, без аккаунта, данные актуальные. По каждому рынку за
день — цена открытия, максимум, минимум, закрытие, цена расчёта и открытый
интерес, то есть полная история движения вероятностей. Покрытие: инфляция (CPI),
решения ФРС по ставке, занятость, заявки на пособия, ВВП, розничные продажи,
строительство жилья, выборы.

**Почему юридически это другой случай:** у остальных мы бы забирали данные из
закрытой системы вопреки её правилам. Здесь они опубликованы, потому что этого
требует регулятор. Страницу с условиями использования мы искали и не нашли —
хотя отсутствие правил и письменное разрешение это не одно и то же.

**Проверить в первую очередь:** основной объём торгов там — в *погодных* рынках.
Экономические рынки существуют, но хватает ли в них денег, чтобы цифрам можно
было верить, мы не измеряли.

## Предложение

Новостной стек оставляем как есть — здесь ничего не меняется. **Пробуем
ForecastEx.** Данные скачиваются уже сегодня, без переговоров, и хорошо ложатся
в небольшую фичу: чего рынок ждёт от следующего отчёта по инфляции или заседания
ФРС. Новости этого дать не могут, потому что сообщают об уже случившемся.

Параллельно отправить им одно письмо с вопросом, можем ли мы показывать их цены
со ссылкой на источник — дёшево, и превращает «запретов не нашли» в письменный
ответ. Kalshi и Polymarket к рабочей системе без письменного соглашения не
подключаем; интеграцию Polymarket можно подготовить на синтетических данных.
